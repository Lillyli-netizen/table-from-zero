# 22 候选、哈希和回退

[目录](../README.md)｜先修：[合成验证集](21_合成验证集自己画表考模型.md)｜下一章：[账本和断点续跑](../06_跑完整流程/23_账本和断点续跑.md)

## 1. 版本纪律

每个候选文件有五件套：xlsx、改动清单（patch）、逐题证据、SHA-256、预检结果。历史文件永不覆盖，新实验进新目录。

```
out/coord/v47audit_20261122/
  submission_v47_audit.xlsx      # 候选
  patch_v47.json                 # 逐题证据
  REPORT.md                      # 全部裁定
```

## 2. 候选从原始记录重建

改动只能从模型的原始响应重建，从旧高分文件抄答案等于把别人的判断当成自己的证据。底稿复制 908 行，逐题替换，替换处写明出处。

## 3. 回退是一条随时能走的路

分数降了就把上一版原样重交。回退不丢人：负收益实验的价值是证伪，v47 一次提交回退，换来"操作数必须逐字定位"这条铁规则。

## 4. 审计自己：矛盾必须查

某轮报告写"采纳 10 题、改动 12 题"，数字对不上。用程序重放：冻结集合 19、采纳规则重算一致、12 ⊆ 19、差集 7 全部来自审计回退。结论是报告笔误，文件哈希不变。数字对不上的时候，怀疑报告，不怀疑规则。

## 5. 练习

1. 给一个候选目录写五件套清单。
2. 写回退脚本：输入版本号，校验哈希后重交。
3. 复盘一次你自己的数字矛盾。
