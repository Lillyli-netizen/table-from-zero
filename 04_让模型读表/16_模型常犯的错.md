# 16 模型常犯的错

[目录](../README.md)｜先修：[票数多数和口径分歧](15_票数多数和口径分歧.md)｜下一章：[结构检查](../05_验证和修正/17_结构检查网格闭合越界重叠.md)

## 1. 六类高频错误

| 错误 | 例子 | 识别方法 |
|---|---|---|
| 截断 | JSON 写一半 | finish_reason=length |
| 字段当答案 | 答"性别"而不是"男" | 答案==行标签 |
| 漏负号 | 会计括号 `(100)` 读成 `100` | 对照 basis 里的原文 |
| 读错行 | 下一行的值 | 行标签定位复核 |
| 网格不自洽 | nrows 写小、格子越界 | 尺寸重算 |
| 扁平化 | 键值表拼成一行 | 配对复核 |

## 2. 漏负号值得单独一节

相应会计列中括号常表示负数，其他括号可能表示编号或注释，需核对上下文。模型读图经常只报 `100`。识别办法：要求模型同时输出答案和它看到的原文（basis），原文带括号而答案不带，就是丢了符号。真实案例：id733 两路都报 100，basis 里躺着 `(100)`，改动被回退。

## 3. 错误分类是修复的前提

把失败响应按原因分组：截断、无 JSON、口径歧义、网络失败、字段混淆。一组一组修，一组一个统一办法。逐题手修既慢又会引入不一致。

## 4. 每次拿到模型输出先扫四眼

1. finish_reason。
2. 答案是否等于某个行标签。
3. 数值符号和原文符号是否一致。
4. JSON 结构是否完整闭合。

## 5. 练习

1. 给六类错误各造一个例子。
2. 写一个"答案==行标签"检测函数。
3. 用 basis 对照法检查三条真实输出里的符号。
