# 11 多模态模型吃图：base64 和压缩

## 1. 图片怎么进请求

多模态接口收两种图：URL 或 base64。本地文件走 base64：

```python
b = io.BytesIO()
img.convert("RGB").save(b, "JPEG", quality=88)
b64 = base64.b64encode(b.getvalue()).decode()
```

请求体里写成 `data:image/jpeg;base64,<编码>`。

## 2. 字节链路的三道闸

| 闸 | 限制 | 处理 |
|---|---|---|
| 接口单图上限 | 约几十万字节级 | 压缩到限额内 |
| token 计费 | 图片按像素折 token | 尺寸直接影响成本 |
| 清晰度 | 太小数字看不清 | 不能压过头 |

比赛链路的平衡点：DPI 170 渲染，长边 2600，JPEG 质量 90，超了再降到 1100。每张图编码前都记录字节，超限降级的写进日志。

## 3. 成本要按价格预留

调模型前先算账：输入 token × 输入单价 + 输出 token × 输出单价。一轮真实调用 20 次花 0.30 元，单次 0.005–0.06 元不等，差额来自图片大小和输出长度。

## 4. 每次调用前过三关

1. 图片字节降到位了吗？
2. 这一次调用的预算预留了吗？
3. finish_reason 和 usage 会记进日志吗？

## 5. 练习

1. 同一页按质量 90 和 60 各存一次，对比字节和清晰度。
2. 算一张 1406×1991 图的 base64 大小。
3. 给自己的调用写一个记费日志函数。
