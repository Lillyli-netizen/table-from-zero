# 24 失败分类和修复队列

[目录](../README.md)｜先修：[账本和断点续跑](23_账本和断点续跑.md)｜下一章：[全流程清单](25_全流程清单.md)

## 1. 失败先分组再修

一整批失败响应按原因分组，每组配一个统一修法：

| 组 | 特征 | 统一修法 |
|---|---|---|
| 截断 | finish=length | 改局部取证 |
| 无 JSON | 响应夹解释 | 契约收紧 + 格式重问 |
| 口径歧义 | 模型间 2:1 | 枚举合同 + 程序计数 |
| 网络失败 | 无 usage | 换路重试一次 |
| 字段混淆 | 答案=行标签 | 归属校验 |

## 2. 队列排序原则

优先修"原因明确、一个办法能覆盖多题"的组。一条统一修法救 10 题的组排前面，逐题解释成因的组排后面。

## 3. 每组修完记录三样

1. 进组多少题、修好多少、剩多少。
2. 修法的契约版本。
3. 剩余题移到哪个新组。

修不完的组如实报告，不为了凑产出放宽门槛。

## 4. 退役机制

反复修不动的路线写退役报告，列明停止原因，避免两周后换个名字重跑一遍。真实项目里退役过的路线：整表结构直出、纯文本操作数复算、通用换提示重问。

## 5. 练习

1. 把你自己的一批失败响应分进五组。
2. 给每组写出统一修法或退役理由。
3. 算一算：优先级最高的组能救几题。
