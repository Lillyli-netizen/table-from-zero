## 1. 账本三件事

| 记什么 | 例子 |
|---|---|
| 钱 | spent: 19.9493 元 |
| 次 | calls: 276 次 |
| 上限 | CAP_MONEY / CAP_CALLS |

每次调用后立即写账：`spent += fee`、`calls += 1`。调用前预留费用与次数，预算不足时停止新调用，重试也占预算。预算是授权的一部分，超支等于违规。

## 2. 断点续跑

批次脚本开始时先数已完成调用，续跑按请求身份与完成状态去重，不能只数 JSON 文件：

```python
done = [f for f in os.listdir(RAW) if f.endswith(".json")]
n_call = len(done)
spent = sum(json.load(open(os.path.join(RAW, f)))["fee"] for f in done)
```

每个响应落盘时存 fee、request_id、usage、finish_reason。中断后能从盘上恢复全部状态。

## 3. 失败不计费的部分

网络超时可能发生在服务端已执行且计费后。没有 usage 时标记费用未知，用 request_id 和账单核对，但都记进日志。404 可能来自模型名、端点、地区或权限错误：立即关闭该路径，换可用模型，别对着同一个报错重试。

## 4. 每批跑完出一张小账

本批用了几次、花了多少、账本余额多少。批次之间不许因为"这批没产出"临时换策略，既有授权与预算内可调整诊断策略，扩展预算或范围时再确认。
