# 25 全流程清单

[目录](../README.md)｜先修：[失败分类和修复队列](24_失败分类和修复队列.md)｜下一章：无（本仓库完）｜实践仓库：[electronics-from-zero](https://github.com/Lillyli-netizen/tianchi-table-pipeline)

## 1. 从零到提交的完整顺序

1. **文件分诊**：全部来源文件跑文本层检测，分"文本可用 / 纯图"两堆。
2. **格式预解析**：908 题按 answer_format 分四种，写严格解析器。
3. **文本路线**：先尝试程序检索与计算，复杂语义可结合模型，带坐标溯源。
4. **模型路线**：纯图题喂图，局部证据契约，temperature=0。
5. **投票**：记录多路依赖，采用经验证的采纳规则，口径题走枚举计数。
6. **核验**：bbox、归属、单位、符号、口径五项检查。
7. **冻结与改动**：采纳集合冻结后才比底稿，改动清单逐题带证据。
8. **预检五项**：行数、id、格式、回读、哈希。
9. **提交与记账**：交卷，记录分数和哈希，绑定成历史。
10. **复盘**：涨了找原因，下降时恢复默认基线、分析原因，再决定是否停止。

## 2. 三条贯穿全程的纪律

1. **证据先行**：每个改动都有原始响应可回放，哈希存档。
2. **规则冻结**：采纳规则在跑票之前写死，跑完不改。
3. **账本诚实**：钱、次数、失败全部如实落盘，触顶即停。

## 3. 常见误区对照

| 误区 | 正确做法 |
|---|---|
| 模型说多少就是多少 | 程序从枚举计数 |
| 能解析就算对 | 结构合法才谈对错 |
| 格式改了没扣分，说明格式不重要 | 只实测了 number 的部分形态，边界要写清 |
| 高分文件抄答案提分快 | 抄来的答案没有证据，审计时全部作废 |
| 分数不涨就是白干 | 证伪一条路线 + 8 题留档，也是净进展 |

## 4. 毕业动作

把本仓库 25 章的练习做完，然后在实验仓库跑通一遍完整流程：从文件分诊到一份带哈希的提交。跑通了，你就有了自己的一套表格识别流水线。
